# TennisMirror — план разработки

PWA для тренировки техники настольного тенниса. Экран делится на две части: живая камера
и эталонный контент (видео/фото из загруженного пака). Пропорции меняются перетаскиванием
линии между частями. Есть режим «камера на весь экран» и режим наложения эталона поверх камеры.

## 0. Решения

- **PWA**: устанавливается из браузера на домашний экран, без App Store / Google Play.
- **Cloudflare R2** для файлов паков (10 ГБ бесплатно, исходящий трафик бесплатный).
- Паки публикует **только владелец** — скриптом, без админки. У пользователей нет аккаунтов.
- Записи и фото сначала сохраняются **на устройстве**, потом загружаются в облако (раздел 2.9).
- **Сейчас делаем локальную версию** (фазы 0–7). Vercel, R2 и загрузка в облако — фаза 8.
- Зум камеры — **только нативный** (как в родной камере телефона), цифрового нет.
- Проект **личный**, но с заделом под коммерцию (раздел 3.1). Сейчас делаем только личную часть.
- Поддержка: iOS 16.4+ (Safari), Android Chrome 110+.

  Запись — 720p 30 кадров/с.

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| UI | React 19 + TypeScript strict + Vite | задано; быстрая сборка |
| Состояние | Zustand (~1 КБ) + persist в localStorage | селекторы, нет лишних ре-рендеров |
| Стили | чистый CSS по фичам, без UI-китов | минимальный бандл, без анимаций |
| PWA | vite-plugin-pwa (Workbox) — только оболочка | офлайн-запуск, установка на экран |
| Хранилище на устройстве | IndexedDB через idb-keyval (<1 КБ) | Blob-ы паков и записей |
| Хостинг | Vercel Hobby, статический SPA | задано; превью на каждый PR |
| Файлы паков | Cloudflare R2 | бесплатный трафик на видео |
| Тесты | Vitest (логика) + ручной прогон на устройствах | камеру не проверить в эмуляторе |

Роутер не нужен: один экран плюс нижняя шторка выбора пака. Бюджет JS ≤ 90 КБ gzip.

## 2. Архитектура

```
Телефон (PWA)
 ├─ Камера: getUserMedia → <video> (никогда не размонтируется)
 │    ├─ MediaRecorder → Blob → IndexedDB → «Мои записи» / Поделиться
 │    └─ кадр → canvas → фото
 ├─ Контент: карусель scroll-snap → <video>/<img> из Blob URL
 └─ Паки: R2 (index.json → manifest.json → файлы) → IndexedDB (офлайн)

Vercel      — статика + (фаза 8) функции api/ для записей в облаке
Cloudflare  — R2-бакет с паками (+ опционально Worker для раздачи)
```

Ключевое: DOM один и тот же во всех режимах. Камера не запрашивается заново, видео контента
не перезагружается и не теряет позицию.

### 2.3 Разделитель

- Pointer Events + `setPointerCapture`; зона захвата ≥ 24 px, видимая линия 4 px.
- Во время перетаскивания меняется только `--split` на корне (в rAF) — React не перерисовывается.
- На `pointerup` значение уходит в store (и в localStorage).
- Ось (Y/X) и инверсия при swapped вычисляются из ориентации и флага.
- Ограничение 15–85 %, двойной тап — сброс на 50/50.

### 2.4 Режимы и HUD

- **split** — камера | разделитель | контент.
- **camera** — камера на весь экран, контент скрыт и на паузе.
- **overlay** — камера на весь экран + эталон поверх, слайдер прозрачности 0–100 %,
  щипок/перетаскивание эталона, чтобы совместить фигуру со своей, кнопка «зеркало».
  Свайп в этом режиме выключен (жесты = выравнивание), клипы переключаются кнопками ‹ ›.
- **Скрыть HUD** — отдельная кнопка. Когда HUD скрыт, остаётся одна маленькая полупрозрачная
  кнопка в углу, иначе интерфейс не вернуть.
- На iPhone Fullscreen API для обычных элементов не работает, поэтому «на весь экран» =
  раскладка на 100 % вьюпорта + standalone-режим PWA. На Android дополнительно `requestFullscreen()`.

### 2.5 Камера

- `getUserMedia({ video: { facingMode, width: {ideal: 1280}, height: {ideal: 720}, frameRate: {ideal: 30} } })`.
- `<video autoplay muted playsinline>`; фронтальная камера зеркалится в превью через `scaleX(-1)`.
- Кнопка фронт/тыл. Звук при записи — настройка (по умолчанию выкл., чтобы не спрашивать микрофон).
- `visibilitychange: hidden` → остановить треки (батарея), при возврате — перезапустить.
- Screen Wake Lock — экран не гаснет на тренировке (если поддерживается).

**Зум камеры — только нативный.** Зумит сам телефон, как в родной камере: переключает объективы
и кадрирует на сенсоре. Результат сразу попадает в превью, запись и фото в полном качестве,
без нагрузки на приложение. Цифрового зума (растягивания картинки) нет.

1. **Основной путь — `zoom` у трека камеры.** `track.getCapabilities().zoom` даёт `{min, max, step}`,
   зум меняется через `applyConstraints({ advanced: [{ zoom }] })`, не чаще раза в ~50 мс.
   - Android Chrome — поддерживается.
   - iPhone — реализация есть в движке Safari (WebKit, 2024: зум до 10× на камерах, которые это умеют),
     но сторонние источники пишут обратное. **Проверяем на реальном iPhone в фазе 0.**
2. **Запасной путь — переключение объективов.** С iOS 16.3 Safari отдаёт объективы (сверхширокий,
   основной, телевик) как отдельные камеры в `enumerateDevices()`. Кнопки 0.5× / 1× / 3× переключают
   `deviceId` — это тоже настоящая оптика. Названия объективов переведены на язык системы и
   `deviceId` меняются, поэтому объектив определяем по списку при каждом запуске.
3. **Если нет ни того, ни другого** (например, у фронтальной камеры) — кнопок зума просто нет.

Управление: щипок по превью камеры + кнопки-пресеты, которые строятся из реального диапазона
`min…max` конкретного телефона. Зум через `zoom` можно менять во время записи — он попадёт в видео.
Переключение объектива во время записи недоступно: это перезапуск камеры, запись прервётся.

**Запись:** MediaRecorder, mimeType по порядку: `video/mp4;codecs=avc1` → `video/mp4` →
`video/webm;codecs=vp9` → `video/webm`. Готовый Blob → IndexedDB → появляется в паке
«Мои записи» в панели контента (сразу сравнить себя с эталоном) + «Поделиться»
(`navigator.share` с файлом → «Сохранить видео» в Фото/Галерею) или скачивание.
Индикатор записи — статичная красная точка и таймер, без мигания.

**Фото:** текущий кадр `<video>` (уже с нативным зумом) → canvas → `toBlob('image/jpeg', 0.9)` → туда же.

### 2.6 Контент

- Карусель: горизонтальный `scroll-snap-type: x mandatory` — нативный свайп, ноль JS.
- Активный слайд — через IntersectionObserver.
- `src` у `<video>` есть **только у активного** слайда; у соседей — постер `<img>`.
  При уходе со слайда: `pause()` + снятие `src` (память и декодер на iOS).
- Видео: тап — пауза/пуск; скорость 0.25 / 0.5 / 1×; кадр ±1 (для разбора техники);
  ползунок перемотки (обновление по `timeupdate`, не в rAF); повтор по кругу; звук выключен.
- **Зум видео и фото** — общий хук `usePinchZoom`: pointer events, `transform` пишется
  напрямую в style, масштаб 1–5×, пан, двойной тап — сброс.
  При масштабе 1 — `touch-action: pan-x` (свайп нативный); при > 1 — `touch-action: none`
  и `overflow: hidden` у карусели, чтобы пан не листал слайды.
- «Зеркало» эталона для левшей — `scaleX(-1)`.
- Свои файлы из галереи: `<input type="file" accept="video/*,image/*" multiple>` → локальный пак.

### 2.7 Паки и хранилище

Структура R2:

```
packs/index.json                          список паков (id, title, version, size, cover)
packs/<packId>/v<ver>/manifest.json
packs/<packId>/v<ver>/01.mp4  01.jpg  02.webp …
```

```json
{ "schemaVersion": 1, "id": "forehand-topspin", "title": "Накат справа", "version": 3,
  "items": [
    { "id": "01", "type": "video", "src": "01.mp4", "poster": "01.jpg", "w": 1280, "h": 720, "duration": 8.4 },
    { "id": "02", "type": "image", "src": "02.webp", "w": 1600, "h": 1200 }
  ] }
```

- Версия в пути → файлы неизменяемые → `Cache-Control: public, max-age=31536000, immutable`.
- «Скачать пак» → fetch всех файлов с прогрессом → Blob в IndexedDB → воспроизведение через
  `URL.createObjectURL`. Работает офлайн в зале и надёжнее на iOS, чем кэш видео в Service Worker
  (там ломаются Range-запросы). Blob URL обязательно `revokeObjectURL` при смене пака.
- `navigator.storage.persist()`; показывать размер пака и `navigator.storage.estimate()`; кнопка «Удалить пак».
- CORS бакета: `AllowedOrigins: ["*"]` (контент и так публичный), `GET, HEAD`,
  `AllowedHeaders: ["Range"]`, `ExposeHeaders: ["Content-Length", "Content-Range", "ETag"]`.

**Подготовка видео** — H.264, 720p, частые ключевые кадры для плавной покадровой перемотки, faststart:

```bash
ffmpeg -i in.mov -vf "scale=-2:720" -c:v libx264 -crf 23 -g 15 -an -movflags +faststart 01.mp4
ffmpeg -i in.mov -frames:v 1 -vf "scale=-2:360" 01.jpg
```

Фото — WebP или JPEG, длинная сторона ≤ 2000 px.

**Публикация пака (без админки):** `scripts/publish-pack.mjs` — кодирует через ffmpeg, делает
постеры, пишет manifest, обновляет index.json, загружает в R2 по S3-API (rclone или
`@aws-sdk/client-s3` как dev-зависимость — в бандл не попадает).

Ключи доступа к R2 — только в `.env.local` на компьютере владельца, в репозиторий и на Vercel не попадают.

### 2.8 Установка PWA на домашний экран

- `manifest.webmanifest`: `name`, `short_name`, `start_url: "/"`, `display: "standalone"`,
  `orientation: "any"`, `background_color`, `theme_color`, иконки 192 и 512 px + `maskable`.
- iOS: `apple-touch-icon` 180 px, `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">`,
  `viewport-fit=cover`. Сплэш-экраны не делаем (лишний вес).
- Service Worker (vite-plugin-pwa, `registerType: 'autoUpdate'`) кэширует оболочку — приложение
  открывается без сети. Видео паков в SW не кэшируются (они в IndexedDB, раздел 2.7).
- **Android:** ловим `beforeinstallprompt` и показываем свою кнопку «Установить».
- **iOS:** системного запроса установки нет. Если приложение открыто в Safari, а не с экрана
  (`navigator.standalone === false`), показываем подсказку: «Поделиться → На экран „Домой“». Один раз, с крестиком.
- Обновления: новая версия подхватывается при следующем запуске, без модальных окон.

### 2.9 Загрузка записей в облако (фаза 8)

- Отдельный **приватный** бакет R2 для записей (паки — публичный бакет, записи — нет).
- Сервер — 2–3 функции Vercel в `api/` (тот же репозиторий и домен). Они выдают временные
  подписанные ссылки на загрузку, просмотр и удаление и отдают список записей. Ключи R2 — только в env Vercel.
- Видео идёт с телефона **напрямую в R2** по подписанной ссылке: тело запроса к функции Vercel ограничено 4,5 МБ.
- Доступ — личный ключ (длинная случайная строка в env Vercel), вводится один раз на каждом устройстве.
  Потом заменяется аккаунтами (раздел 3.1).
- Поток: запись сохраняется локально → очередь в IndexedDB → загрузка с прогрессом (XHR) → «в облаке» →
  по желанию удалить локальную копию. Очередь переживает перезапуск, при ошибке файл грузится заново.
- iOS не загружает в фоне: загрузка идёт, пока приложение открыто.
- Главная польза: записал на iPhone — смотришь на большом экране планшета (вкладка «Облако» в «Мои записи»).
- Место: битрейт записи 2,5 Мбит/с (≈ 19 МБ/мин), индикатор занятого места, предупреждение на 80 % от 10 ГБ,
  по желанию — правило R2 на автоудаление записей старше N дней.
- Ключи объектов с заделом под пользователей: `u/<ownerId>/rec/<год>/<месяц>/<id>.mp4` + `<id>.json`
  (дата, длительность, устройство, эталон). Отдельная база данных не нужна.

## 3. Бесплатные лимиты

| Сервис | Лимит | Что это значит |
|---|---|---|
| R2 | 10 ГБ, 1 млн записей и 10 млн чтений в месяц, трафик бесплатно | ≈ 2 500 клипов по 10 с в 720p |

| R2 сверх лимита | $0,015 за ГБ в месяц; чтобы включить R2, Cloudflare просит карту | 20 ГБ записей ≈ $0,15 в месяц |
| Vercel Hobby | только **некоммерческое** использование, 100 ГБ трафика/мес | для личного проекта подходит; статике хватит с запасом |

### 3.1 Задел под коммерцию (сейчас не делаем)

Сейчас строим только личную версию, но так, чтобы потом не переписывать:

- **Хостинг переносимый.** Приложение — чистая статика, поэтому переход на Vercel Pro или
  Cloudflare Pages (бесплатно, коммерция разрешена) — это смена настроек, не кода.
- **Паки — через одну точку.** Весь доступ к пакам идёт только через `packs/api.ts`.
  Потом там же появятся авторизация и подписанные ссылки, остальной код не меняется.
- **Формат паков с версией.** В `index.json` и `manifest.json` есть `schemaVersion`. Поле
  `access: "free" | "paid"` предусмотрено в типах, но UI его пока игнорирует.
- **Путь к платным пакам потом:** закрытый бакет R2 + Cloudflare Worker, который после проверки
  доступа выдаёт временную ссылку. Там же — вход (Cloudflare Access / сторонний сервис) и оплата.
- **Свой домен** покупаем при запуске коммерции: он же снимает лимит r2.dev.
- **Сейчас не делаем:** аккаунты, оплату, аналитику, политику конфиденциальности, мультиязычность.

## 4. Правила кода

Полный список — в [CLAUDE.md](../CLAUDE.md). Главное: **≤ 400 строк в любом файле кода**.

ESLint (`eslint.config.js`):

```js
rules: { 'max-lines': ['error', { max: 400, skipBlankLines: false, skipComments: false }] }
```

ESLint не проверяет CSS, поэтому есть отдельный скрипт `scripts/check-lines.mjs`:

```js
import { readdirSync, readFileSync, statSync } from 'node:fs';
import { join, extname } from 'node:path';

const MAX = 400;
const EXT = new Set(['.ts', '.tsx', '.js', '.mjs', '.css']);
const SKIP = new Set(['node_modules', 'dist', 'dev-dist']);
const bad = [];

(function walk(dir) {
  for (const name of readdirSync(dir)) {
    if (SKIP.has(name) || name.startsWith('.')) continue;
    const path = join(dir, name);
    if (statSync(path).isDirectory()) walk(path);
    else if (EXT.has(extname(path))) {
      const text = readFileSync(path, 'utf8');
      const lines = text.split('\n').length - (text.endsWith('\n') ? 1 : 0);
      if (lines > MAX) bad.push(`${path}: ${lines}`);
    }
  }
})('.');

if (bad.length) {
  console.error(`Файлы длиннее ${MAX} строк:\n${bad.join('\n')}`);
  process.exit(1);
}
```

`package.json`: `"check:lines": "node scripts/check-lines.mjs"`,
`"build": "npm run check:lines && tsc -b && vite build"` — Vercel не задеплоит нарушение.

`vercel.json`: заголовок `Permissions-Policy: camera=(self), microphone=(self)` и
`Cache-Control: public, max-age=31536000, immutable` для `/assets/*`.

## 5. Структура проекта

## 6. Этапы

Фазы 0–7 — **локальная версия**: без Vercel и R2, паки лежат в `public/packs/` в той же структуре,
что потом будет в R2 (переключение — одна переменная `VITE_PACKS_BASE_URL`). Облако — фаза 8.

**Фаза 0 — подготовка (0,5–1 дня)**
- Vite + React + TS strict, ESLint с `max-lines`, `check-lines` в build, Prettier.
- HTTPS на телефоне: `@vitejs/plugin-basic-ssl` + `vite --host` (та же Wi-Fi-сеть) или
  `cloudflared tunnel --url http://localhost:5173` (если компьютер в другой сети).
- **Проверка камеры (`public/probe.html`, ~80 строк):** показывает `getSupportedConstraints()`,
  `getCapabilities()` (есть ли `zoom`, диапазон, максимум кадров/с), список камер из `enumerateDevices()`,
  ползунок зума, поддерживаемые форматы MediaRecorder, размер экрана в CSS-пикселях и `devicePixelRatio`.
  Открыть на iPhone 16 Pro (Safari) и на Digma (Chrome), результаты записать в таблицу раздела 0.1.
- *Готово:* пустое приложение открывается по HTTPS на iPhone и планшете,
  известно, какой путь зума (раздел 2.5) работает на каждом устройстве.

**Фаза 1 — каркас экрана (1–2 дня)**
- Store, корневая раскладка, разделитель, portrait/landscape, кнопка swap. Вместо камеры и контента — заглушки.
- *Готово:* 4 раскладки корректны, safe-area учтены, перетаскивание 60 fps и 0 ре-рендеров
  React во время движения (проверить в Profiler).

**Фаза 2 — камера (2 дня)**
- `useCamera`, фронт/тыл, зеркало, остановка в фоне, wake lock.
- Нативный зум: `zoom`-констрейнт, запасной путь — переключение объективов; пресеты из диапазона телефона.
- Режим «камера на весь экран», скрытие HUD.
- *Готово:* камера не перезапускается при смене режима, раскладки и повороте; зум ведёт себя как
  в родной камере на обоих телефонах.

**Фаза 3 — контент (2 дня)**
- Карусель, `Slide`, `VideoControls`, `usePinchZoom`, зеркало эталона.
- Пока файлы берутся из галереи устройства — облако ещё не нужно.
- *Готово:* свайп листает, зум не конфликтует со свайпом, одновременно декодируется не больше одного видео контента.

**Фаза 4 — запись и фото (2 дня)**
- `useRecorder`, `photo`, IndexedDB, пак «Мои записи», «Поделиться»/скачивание.
- *Готово:* запись воспроизводится в панели контента и сохраняется в Фото/Галерею на обеих платформах.

**Фаза 5 — режим наложения (1 день)**
- Эталон поверх камеры, слайдер прозрачности, выравнивание щипком, зеркало, кнопки ‹ ›.
- *Готово:* split ↔ camera ↔ overlay переключаются без чёрных кадров и перезапуска видео.

**Фаза 6 — паки и офлайн (2–3 дня)**
- `packs/api.ts`, `packs/storage.ts`, `PackSheet` (скачать с прогрессом / удалить / место), `persist()`.
- `scripts/publish-pack.mjs` — пока кладёт пак в `public/packs/`.
- PWA (раздел 2.8): manifest, иконки, SW для оболочки, кнопка «Установить» на Android, подсказка на iOS.
- *Готово:* приложение ставится на домашний экран iPhone и Android, в авиарежиме запускается,
  скачанный пак работает.

**Фаза 7 — полировка и релиз (2 дня)**
- Прогон по матрице устройств, профилирование батареи и нагрева (30 мин работы), бюджет бандла.
- Опционально: запись 60 fps (замедленный разбор ударов), повтор отрезка A–B.

**Фаза 8 — облако (3–4 дня)**
- GitHub → Vercel (превью на каждый PR). R2: публичный бакет паков + CORS, `publish-pack.mjs` грузит в R2.
- Записи в облако (раздел 2.9): приватный бакет, функции `api/`, очередь загрузки, вкладка «Облако».
- *Готово:* запись с iPhone видна и воспроизводится на планшете; паки приходят из R2.

**Итого:** ≈ 16–20 рабочих дней для одного разработчика.

## 7. Тестирование

- **Vitest:** логика store; геометрия разделителя (позиция → доля с учётом swap и ориентации);
  математика щипка; выбор mimeType; разбор manifest.
- **Матрица устройств:** iPhone 16 Pro (Safari и PWA с экрана «Домой») и Digma Pro Evolution
  (Chrome и установленная PWA) × портрет/альбом × фронт/тыл. На iPhone — все три объектива.
- **Сценарии:** поворот во время записи; сворачивание во время записи; входящий звонок;
  мало места на устройстве; обрыв сети во время скачивания пака.
- **Метрики (меряем на планшете, он слабее):** JS ≤ 90 КБ gzip; холодный старт < 2 с на 4G;
  разделитель 60 fps; 30 минут без утечек памяти (Blob URL освобождаются) и без заметного нагрева.

## 8. Подводные камни и риски

| Риск | Что делаем |
|---|---|
| iOS: видео не играет инлайн | `playsinline muted` везде |
| iOS: `100vh` врёт, вырез экрана | `100dvh`, `viewport-fit=cover`, `env(safe-area-inset-*)` |
| iOS: системный зум страницы мешает щипку | `touch-action` на зонах жестов + `preventDefault` на `gesturestart` |
| iOS: нет `screen.orientation.lock` | ориентация только через CSS, в manifest `orientation: any` |
| iOS PWA повторно спрашивает камеру | поведение системы; не останавливать поток без нужды (только в фоне) |
| iPhone может не отдать `zoom` | проверка в фазе 0; запасной путь — объективы; иначе без зума |
| iOS сам переключает объективы на ходу | известное поведение Safari; для записи техники не критично |
| Android пишет webm, iOS — mp4 | записи локальные, играются на том же устройстве; при «Поделиться» предупреждать о формате |
| Поворот во время записи меняет размер кадра | проверить на устройствах; при проблемах — фиксировать ориентацию записи на старте |
| iOS чистит хранилище сайтов | `storage.persist()`, подсказка «Установить на экран» |
| r2.dev ограничен по скорости | для личного использования хватит; позже — Worker или свой домен |
| Vercel Hobby — не для коммерции | при монетизации — Pro или Cloudflare Pages (раздел 3.1) |
